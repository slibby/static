Item types

The tiers and flows on the other tabs name things like web scene, scene service and 3D tiles layer without saying what they actually are. This is that reference — what each item type is, what creates it, and where ArcGIS Enterprise and ArcGIS Online genuinely differ.

Two naming traps

Both cause real confusion in customer conversations

1. Almost every 3D item has three different names

The REST API type, the name shown in the portal, and the name used in the documentation all differ — and Esri is mid-rename, which makes it worse. At 12.1 the docs now call the whole family “3D layers” rather than “scene layers,” but the item names still say scene and 3D tiles. Esri's own note: “the layer item names still include the words scene and 3D tiles… to help you move from the old item names to the new consolidated name.”

3DTilesService→3D Tiles Layer→3D layer

2. “Data store” means two unrelated things

Same words, opposite products, no relationship.

In ArcGIS Enterprise a data store item registers a folder, database or cloud storage location with a federated server so layers can reference data instead of copying it. This is the mechanism that makes very large 3D content practical.

In ArcGIS Online a data store item is an ArcGIS Data Pipelines source connection — an ETL input. It has nothing to do with 3D caches.

Consequence: ArcGIS Online has no referenced-cache mechanism for 3D at all. Every 3D layer in Online is hosted, the cache is copied into Esri's storage, and it counts against credits. This is the defining Enterprise advantage for industrial-scale 3D, and the data store item is the object that enables it.

ArcGIS Enterprise vs. ArcGIS Online

Where each component actually runs. For industrial digital twin work the deciding factors are usually cache size, referenced-cache publishing, server roles, and data sovereignty — summarised below the matrix.

The four decisions that usually settle it

1. How big is the 3D cache?

Esri guidance puts i3sREST referenced content as the right answer above roughly 200 GB, and referenced-cache publishing is an Enterprise-only pattern. ArcGIS Online caps package upload at 500 GB and offers no data-store referencing. A full refinery mesh plus point clouds crosses that line quickly.[1]

2. Do you need server roles?

Image Server, Reality Server, Knowledge Server, Velocity Server, Notebook Server and Data Pipelines Server are Enterprise-only licensing roles. If reality mapping at scale, knowledge graphs, or raster analytics are in scope, that is an Enterprise conversation.[2]

3. Credits vs. infrastructure

In ArcGIS Online, 3D layer, SLPK and 3D tiles caches are billed at 1.2 credits per GB per month. Enterprise consumes no credits but you own the object store, the caching tier and the sizing. Model both before recommending.[3]

4. Where does the plant data live?

Operational-technology adjacency, air-gapped sites and data-residency rules push toward Enterprise on-premises or in the customer's own cloud tenancy. Kubernetes is available but is not at feature parity — notably no Velocity, no Knowledge, no Data Interoperability.[4]

Notes, release caveats & known gaps

Everything on this page is stated against ArcGIS Enterprise 12.1 (May 2026), ArcGIS Enterprise 12.1 on Kubernetes (June 2026), ArcGIS Pro 3.7 and the August 2026 state of ArcGIS Online. Where a claim is version-sensitive or unverified, it is called out here rather than smoothed over.

Release-specific caveats

  1. Referenced-cache publishing and size limits. Publish-by-reference (.eslpk, i3sREST content in a registered cloud store, or a 3D tiles dataset) requires ArcGIS Enterprise and a registered folder or cloud storage data store. Esri guidance recommends i3sREST for scene layer content above roughly 200 GB. Copy-data publishing needs 2× the package size free in both the portal content store and the hosting server cache directory. ArcGIS Online caps package upload at 500 GB and has no equivalent referencing path.
  2. Tile cache data store is removed at 12.0. The object store replaced it and is now a required base-deployment component. Any existing 3D deployment on 11.x must migrate hosted scene caches to the object store before upgrading to 12.x. This is a hard upgrade blocker and worth raising early with any customer already running 3D.
  3. ArcGIS Online credit model for 3D. Caches for 3D layers, SLPKs and 3D tiles packages bill at 1.2 credits/GB/month, calculated hourly. Layer generation from features bills separately (1 credit per 1,000 textured multipatch features). Exhausting credits puts the organisation into a restricted state in which members cannot publish layers of any type.
  4. Kubernetes is not at parity. At 12.1 on Kubernetes there is no GeoEvent Server, no Velocity Server, no Knowledge Server, no Data Pipelines Server, and no Data Interoperability. All seven 3D layer types are supported and caches live in the object store (S3/Blob/GCS), but there is no long-term-support release on Kubernetes. Consult the ArcGIS Enterprise Functionality Matrix as the authoritative tiebreaker on any specific capability.
  5. ArcGIS Reality Server is beta. Introduced as a server role at Enterprise 12.0 and still labelled beta at 12.1, distributed via the Early Adopter Community and not covered by Esri Technical Support. It is the right architectural answer for server-side reality mapping at plant scale, but it should be positioned as roadmap, not as something to build a contract around today.
  6. Oriented Imagery Classic is being removed. The Oriented Imagery Catalog (OIC) data model, the Classic Pro add-in, the Classic Experience Builder widget and the Classic API are all deprecated. The Classic widget was removed from ArcGIS Online in February 2026 and will be removed from ArcGIS Enterprise at 12.1+. Maps SDK for JavaScript 5.0 no longer visualises OICs. New work must use the current oriented imagery dataset / oriented imagery layer model.
  7. ArcGIS GeoEvent Server is deprecated. Announced April 2026: final release at Enterprise 12.3, removed at 12.4. ArcGIS Velocity is the designated successor and is now available for Enterprise (Windows/Linux) at 12.1 as ArcGIS Velocity Server — though the Enterprise flavour does not include big data analytics, which remains ArcGIS Online only. Note that Esri is explicit that Velocity Server is not an ArcGIS Server licensing role: it is a standalone federated server component and does not require ArcGIS Server on its machine. Do not design new real-time work on GeoEvent.
  8. ArcGIS GeoAnalytics Server was retired at 11.4. Big data file shares can no longer be registered. Migration paths are the GeoAnalytics desktop toolbox, GeoAnalytics Engine, standard analysis tools, or the ArcGIS API for Python.
  9. CityEngine and Urban licensing consolidated. Perpetual and standalone-subscription CityEngine licences and the ArcGIS Urban Suite are no longer sold; delivery is now via Professional / Professional Plus user types. Both remain urban-planning tools and are not positioned by Esri for industrial plant work — reference them with care in a refinery conversation.
  10. XR Viewer is beta. The no-code VR viewer for existing web scenes (Meta Quest 3/3S) is Early Adopter Program only, with no announced GA date. For a committed immersive-training deliverable today, the supported path is the ArcGIS Maps SDKs for Unity or Unreal Engine — which is a build effort, not configuration.

Industrial proof points

OMV Downstream GmbH — the reference the customer asked about by name. Esri's downstream industry page features OMV's turnaround planning work, and there is a conference video, "OMV Downstream GmbH: Building a 3D Refinery Model," covering the move from 2D to 3D, facility models, visualising work status during turnaround, and connecting to other key systems — explicitly framed against long-term digital twin aspirations. Caveat: the current OMV material is conference video and an industry-page feature, not a formal written case study, and appears to date from around 2021. Verify currency before quoting it.

Other downstream references on Esri's petroleum pages include ExxonMobil (integrated decommissioning workflow; real-estate optimisation), BP (refinery emergency response planning), and Shell Retail. Broader digital twin flagships — Vodafone, Cisco, Cross River Rail (which included a VR design tour), Raleigh Water — are credible but none is a refinery or petrochemical plant. Be candid that the heavy-industry 3D twin reference set is thinner than the utility and urban set.
